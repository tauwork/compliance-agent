# 政策合规智能体 MVP · 操作手册与演示剧本

> 适用版本：v1.0（M1-M3功能全集）｜场景：三资监管·资产处置进场交易｜演示数据全部虚构

## 一、10分钟演示剧本（对领导汇报版）

### 剧本主线：一个新政策如何在一小时内变成一条实时运转的合规流水线

| 步骤 | 页面 | 操作（讲解词要点） | 预期效果 |
|------|------|--------------------|----------|
| 0 开场 | 合规驾驶舱 | "政策→规则→预审→预警→整改全链路指标一屏总览；所有操作哈希链留痕、可防篡改校验" | 指出KPI与闭环运行状态 |
| 1 上传政策 | 政策法规库 | 现场粘贴一份含"第X条"的新政策文本（或用预置的演示二）→ 点"上传并入库" | 政策入库，状态"待拆解" |
| 2 AI拆解 | 政策法规库 | 点"发起拆解"→ 跳转拆解工作台 | 自动切条款、抽义务、生成规则草稿（3条款3义务3草稿） |
| 3 人工门禁 | 政策拆解工作台 | 逐条展示：条款原文→AI义务（责任部门/阈值）→规则DSL草稿；强调"AI只出草稿、人定性"；点"通过并发布" | 草稿→published，规则即时生效 |
| 4 带病申报 | 前置预审 | 提交预置的"未进场+评估超期+挂牌价低+决议缺失"申报单 | 即时红色预审意见单：命中规则逐条附**条款依据+整改建议**；提示"带病提交将生成风险事件" |
| 5 风险预警 | 风险预警 | 切到风险预警页，展示新事件；点"AI归因分析" | 归因结论+整改建议（LLM或降级模板），状态"归因中" |
| 6 审批派单 | 风险预警（弹窗） | 点"批准并派发工单" | 自动创建整改工单（附AI建议），事件→已派单 |
| 7 整改闭环 | 整改闭环 | 泳道视图点按钮走完：派发→执行→复核→关闭 | 复核通过瞬间风险事件自动closed——**闭环完成** |
| 8 回到驾驶舱 | 合规驾驶舱 | 指标已联动更新；点"校验"验证哈希链 | 全链有效；如需演示防篡改：改库中一行数据再校验即报brokenAt |
| 9 对话助手 | 对话助手 | 问"资产转让什么情况可以不进场交易？" | 条款级回答+依据条号溯源 |

**讲解主线一句话**：刚才10分钟内，一份新政策完成了"入库→拆解→发布→拦截了一笔带病申报→归因→派单→整改→闭环"，每一步都留痕可回放——这就是政策合规从"人拉肩扛"到"数字流水线"的差别。

### 应急预案

| 情况 | 处置 |
|------|------|
| DeepSeek API不可用 | 无需处理：拆解/归因/问答自动降级为确定性模板，界面显示"降级模式"，判定链路完全不受影响 |
| 误提交脏数据 | 停应用→`DROP DATABASE pcm; CREATE DATABASE pcm;`→重启→`sh scripts/demo-seed.sh`（2分钟重建演示库） |
| 前端异常 | 刷新；或直接用curl走API演示（见验收脚本） |

## 二、部署手册

### 2.1 Docker部署（推荐，两容器）

```bash
# 前置：Docker Desktop运行中；如需LLM真实调用，在.env或环境变量配 DEEPSEEK_API_KEY
docker compose up -d --build     # 构建+启动 app + mysql
sh scripts/demo-seed.sh          # 灌入演示数据
# API: http://localhost:8080  前端开发模式见2.2
```

### 2.2 本地开发模式

```bash
# 1) 后端（JDK 21+，MySQL 8实例）
mvn clean package -DskipTests
MYSQL_HOST=127.0.0.1 MYSQL_PORT=3306 MYSQL_DB=pcm MYSQL_USER=pcm MYSQL_PASSWORD=pcm123456 \
  java -jar app/target/app-1.0.0-M1.jar

# 2) 前端（Node 18+）
cd web && npm install && npm run dev    # http://localhost:5173（/api自动代理8080）

# 3) 演示数据
sh scripts/demo-seed.sh
```

### 2.3 配置项（环境变量）

| 变量 | 默认 | 说明 |
|------|------|------|
| MYSQL_HOST/PORT/DB/USER/PASSWORD | localhost:3306/pcm/pcm | 数据库连接 |
| DEEPSEEK_API_KEY | 空 | 配置后拆解/归因/问答走DeepSeek；留空自动降级 |
| DEEPSEEK_BASE_URL | https://api.deepseek.com | OpenAI兼容端点 |
| DEEPSEEK_MODEL | deepseek-chat | 主力模型（可切deepseek-reasoner场景见llm-module） |

## 五、LLM降级说明（如实口径）

拆解、归因、问答三个环节支持DeepSeek与确定性降级双路径：配置`DEEPSEEK_API_KEY`后走LLM（结构化JSON提示词），未配置或调用失败自动降级为关键词/模板路径，界面与接口返回标注`mode`。**核心合规判定（规则评估、预审、风险分级）从不依赖LLM**——同一数据+同一规则必得同一结论（可复现、可审计）。
